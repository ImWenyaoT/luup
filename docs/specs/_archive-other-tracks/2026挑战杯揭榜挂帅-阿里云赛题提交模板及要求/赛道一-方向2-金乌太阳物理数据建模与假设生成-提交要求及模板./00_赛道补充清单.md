# JW-FD 赛道补充清单（组委会 → 参赛团队）

本文件仅规定本赛道需补充明确的四项内容，供团队按此准备提交物。

**公开数据：** 百度网盘发布的 **JW-FD 子集**（含 PNG Th1000、FITS、movies、label 及 train/val/test 划分）。解压方式见分卷包内 README。

**重要说明（防造假）：** 公开包中的 test 标签可见，仅用于开发、调参与初评。公开 test 上的优异成绩不能单独作为最终排名依据。组委会将对成绩靠前及抽检队伍进行模型与代码复现；复现通过后，在**专门私有评测数据集**上推理打分。**私有评测集表现优秀者方为最终优胜。** 公开成绩与复现严重不符、无法一键复现、或私有集表现异常崩塌者，取消或降级成绩。

**一并强制要求（写入提交检查项）：**

- 唯一推理入口（例如 `python infer.py --data_root ... --out pred.csv`），禁止只有训练脚本、没有推理脚本。

## ③ 测试指标和验证要求

### 必报指标

对每个声明的评测设定（每个时间窗 × 每个正类定义），须报告：

| 指标 | 说明 |
|------|------|
| TP, FP, TN, FN | 混淆矩阵四格 |
| TSS | True Skill Statistic（Hanssen–Kuipers） |
| HSS | Heidke Skill Score |
| Precision, Recall, F1 | 标准定义；Recall 即 POD |
| FAR, Accuracy | 必报 |
| ROC-AUC, PR-AUC | 若输出概率，建议报告（不均衡时更关注 PR-AUC） |

多分类除宏/微平均 F1 外，须能按声明将预测**折叠为业务二分类**后再算 TSS/HSS，以便横向比较。

统一计算脚本：见 `eval_metrics.py.md`（保存为 `eval_metrics.py` 后运行）。队伍自评与组委会复核应使用同一口径。

### 验证流程（摘要）

详见 `06_评测与防造假协议.md`。

1. **阶段 A（公开初评）：** 队伍提交公开 test 预测与指标表；组委会用统一脚本复核。
2. **阶段 B（复现）：** 对优胜/抽检队伍一键部署，在组委会环境对公开数据复跑；指标须在容差内（默认 \|ΔTSS\|、\|ΔHSS\| ≤ 0.02）。
3. **阶段 C（私有终评）：** 同一推理入口，数据根目录换为私有评测集；**仅本阶段成绩决定最终排名。**

科学约束：不得使用公开 test 标签训练；调参仅用 train/val；禁止时间泄漏与跨 split 混用同一 AR；阈值策略须说明（建议在 val 上选定）。

## ④ 需要重点展示的过程与结果

材料中请突出以下内容，便于初筛与复现验收：

1. **任务设定清晰可复评**（声明与代码、预测文件一致）。
2. **完整指标表**（TSS、HSS、F1、FAR、Accuracy 等必报项），避免只报 Accuracy。
3. **一键复现路径真实可用**（命令、硬件、耗时）。
4. **误差与稀有事件：** 至少 1 组命中与 1 组漏报或虚警分析（尤其 M/X 等稀有正例）。
5. **泛化说明：** 为何认为方法能迁移到未见活动区/时段（呼应私有终评；勿臆测私有集内容）。
6. **简要迭代：** 关键改动前后指标对比即可。
