# 评测与防造假协议

## 1. 数据角色

| 数据 | 是否向队伍公开 | 用途 |
|------|----------------|------|
| JW-FD 子集的 train/val | 是 | 训练与调参 |
| JW-FD 子集的 test（含标签） | 是 | 开发参考与**公开初评** |
| 组委会私有评测集 | **否** | **最终排名** |

私有评测集与公开 JW-FD 子集在任务协议、输入形态上同构，但活动区/时段与公开子集不重叠。具体构成不对参赛队公布。

**公开 test 标签可见，存在对照标签调参或伪造指标的风险。因此：公开成绩只作成绩筛选与复现入口，不以公开成绩单独确定最终名次。**

## 2. 三阶段流程

### 阶段 A — 公开初评

1. 队伍提交：任务声明、指标表、预测 CSV、复现包或开源仓库。
2. 组委会用 `eval_metrics.py`（或等价实现）按声明中的标签列复核预测文件。
3. 指标表与复算结果不一致超过容差的，退回改正；恶意伪造的，取消资格。

### 阶段 B — 复现

1. 对公开成绩靠前队伍及随机抽检队伍，按 `04` / `05` 规范部署环境。
2. 使用队伍提交的推理入口，在组委会机器上对公开 test（全量或约定抽样）重跑。
3. 复算指标与队伍申报值比较：默认要求 **|ΔTSS| ≤ 0.02 且 |ΔHSS| ≤ 0.02**（组委会可赛前公布最终容差）。
4. 复现失败：环境无法安装、无推理入口、权重校验失败、超时、依赖测试标签等 → 通知联系人在响应窗口内**仅修环境**；仍失败则取消进入终评资格。

### 阶段 C — 私有终评

1. 保持与阶段 B 相同的镜像/环境与权重，仅更换 `data_root` 为私有评测集。
2. 按队伍《任务定义声明》生成或对齐私有标签，计算 TSS、HSS、F1、FAR、Accuracy 等必报指标。
3. **最终排名以阶段 C 为准。** 公开第一但私有崩塌者，名次按私有成绩排列。

## 3. 指标定义（与 `eval_metrics.py` 一致）

二分类，正类=1，负类=0：

- \(\mathrm{POD} = \mathrm{Recall} = TP / (TP+FN)\)
- \(\mathrm{Precision} = TP / (TP+FP)\)
- \(\mathrm{FAR} = FP / (TP+FP)\)（无正预测时定义为 0 或 NaN，脚本中按 0 处理并告警）
- \(\mathrm{Accuracy} = (TP+TN) / N\)
- \(\mathrm{F1} = 2 \cdot P \cdot R / (P+R)\)
- \(\mathrm{TSS} = TP/(TP+FN) - FP/(FP+TN)\)
- \(\mathrm{HSS} = 2(TP\cdot TN - FP\cdot FN) / [(TP+FN)(FN+TN) + (TP+FP)(FP+TN)]\)

概率预测另报 ROC-AUC、PR-AUC（若该折全正或全负则跳过并注明）。

多分类：先按声明折叠为二分类，再计算上表；同时可附宏/微 F1。

## 4. 科学与纪律约束

- 禁止使用公开 test 标签训练；禁止将 test 样本及其标签以任何形式注入训练集。
- 禁止时间泄漏（例如用未来帧信息预报过去窗口）。
- 须尊重 JW-FD 子集的 AR 级 train/val/test 划分，不得跨 split 混用同一 AR。
- 阈值建议在 val 上选定并写入声明；组委会保留“只收概率、统一重切阈值”的权利（若启用，赛前通知）。
- 提交物不得含真实密钥；不得攻击评测环境。

## 5. 时限与资源（默认，可赛前调整）

- 单次终评推理墙钟上限：**8 小时**（队伍在 README 中自报预计时间，明显低估且超时仍失败）。
- GPU 环境以组委会届时公告为准；队伍应提供 CPU 回退说明（若可行）或明确“必须 GPU”。

## 6. 异议

对私有集成绩有异议的，可在成绩公布后约定日内申请复核复现日志与指标脚本输入输出；不开放私有样本下载。
