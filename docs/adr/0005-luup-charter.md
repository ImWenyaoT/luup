# ADR-0005 · luup 宪章：四个锚

## 状态

已接受，2026-08-15。用户定稳。

前四份 ADR 各自裁决「某一层选什么」。这一份不裁决选项，它定的是**判据的出处**——
此后一切方向决策引用本文，不再逐次重开。

## 背景

### 摇摆史

luup 到 2026-08-15 为止发生过**四次基底变更**（表在 ADR-0003，不重复），
其后又有**两次以 dsh 为基底的倾向**：

| 日期 | 事件 | 落点 |
|---|---|---|
| 2026-08-14 | ADR-0003 的第一动机是「dsh 借鉴只在 TS 侧可行」——dsh 从参考升格为切栈理由 | `d584107` 起的 `feat/ts-stack` |
| 2026-08-15 | dsh-app spike：以 dsh 为基底重建 luup，地基三点实测 | `f95be86` / `feat/dsh-infra` |

六次的共同形状是同一个：**由「有个东西看起来更好」触发，而不是由「当前方案挡住了哪件
必须交付的事」触发**。缺的不是判断力。ADR 只能裁决被提上来的选项，拦不住选项被无限提上来——
每一次都要从头论证一遍，论证本身就是成本。

四锚补的是这一层：它不回答「选哪个」，它规定**什么算理由**。

### spike 的实测结论不作废，改的是定位

`f95be86` 三点全通，如实记：

- 百炼 route 单轮 3.5s 通。产品路径是 profile + `cordis.patch.yml` 差量层（非自造整树），
  三条差量：填百炼 route、换默认模型、关 `web_search`。
- `session.jsonl.zstd` 33 事件完整落盘。
- `structured_output` 合成工具的流式调用真实发生——不碰 `response_format`，绕开百炼老坑。
- 版本钉在 `@deepseek-ai/dsh@0.1.0-rc.6`（rc.5 未公开发布），传递依赖靠 lockfile 冻结。

两条约束对 luup 有直接效力，与是否搬家无关：

- `outputSchema` 仅 in-process provider 支持；
- dsh 的 JSON Schema 受限子集无 `pattern` / `format` / 数值边界，**B1–B4 的格式校验必须留在宿主侧**。

GO 的是「地基站不站得住」，**不是「该不该搬家」**。后者由本宪章回答，答案是不搬。

### 与 2026-07-06 目标函数的连续性

四锚不是新方向。7-06 的目标函数写的是：下限 = JD ∪ 挑战杯赛题，
**上限 = `../oss/claude_code`（用户单选的主锚）**。四锚把它收敛成可日常引用的形状：
赛题由「下限的一半」升为唯一交付判据，claude_code 保持它本来就有的上限锚位置，
新增的只有理论锚与所有权条款。

## 决定

### 一、目标 = `docs/specs`

XH-202619 赛题（Science-125，截止 **2026-09-05**）。**一切工作以赛题交付为判据。**

一件事进不进 backlog、排在哪，先问它对 2026-09-05 的交付物有没有贡献。交付物是硬清单：
PPT/PDF ≤20 页、可调用 API + 可交互前端入口、代表性案例输入输出、技术报告与源码、
125 题全量输出。判据落点 `docs/design/criteria.md`。

### 二、理论 = `../oss/ai-agent-book`

**设计判据的出处。** 架构层的「该不该做」优先在书里找判据；书自身给出的**否定**判据同样有效
（对齐审计的「明确不做」一节就是这么来的）。

书不是覆盖面清单，不追求把书里的机制做全。

在树内可复核的落点是 `docs/report/book-alignment-audit.md`：十章全文 + 思考题 + 实验，
七路并行对照，结论带 file:line。它是钉在 HEAD `2857769` 的一次性快照，作历史结论读；
喂进它的单章精读明细未入库。

### 三、实践参考 = `../oss/deepseek-harness` 与 `../oss/claude_code`（并列）

**取法不搬家。**

准入判据只有一条：**解决 luup 的实际问题**。不以「与参考对齐」为目标——
「dsh 有而 luup 没有」不是理由；「luup 的某件事被挡住，参考里的某个模式能解开」才是。

现有采纳都是这个形状，台账在 `docs/design/dsh-borrowings.md`：合成工具结构化输出解的是
researcher 唯一不能用 `outputType`；错误码归一解的是 `context_overflow` 落进兜底不可数；
崩溃恢复只取最小版，并写明与 dsh「会话可续跑」的差距是**有意的**。

两个参考并列，不分主次。单条改动可单选一个参考，不必两边都对照。

### 四、所有权 = 我们自己的 luup

用户原话：**「我们去 own 住我们的 luup」**。

luup 的形状由 luup 的交付需求决定。参考的体量、结构、抽象层次都不构成对齐压力——
dsh 是 219 个包，luup 约 3K 行源码，这个差距不是欠账。ADR-0004 已按同一原则处理过顶层形制：
**搬形制不搬体量**。

反面表述更好用：**不存在「luup 应该长得像 X」这条理由。**

### dsh-app spike 的定位

**实践参考的学习件与能力储备，不是迁移前奏。**

- 保留在树内，**不进根 ci 链**（`pnpm-workspace.yaml` 已如此配置）。
- 价值是一份可运行的 dsh 读法（profile 差量层怎么写、百炼怎么接、session 日志长什么样），
  外加上文两条对 luup 有直接约束力的实测结论。
- 不排期、不派生迁移任务、不作为任何设计决策的默认方向。

## 后果

### 正

- **方向决策有了终审判据。** 基底类提议先过准入判据（解决了 luup 的哪个实际问题），
  过不了就不进入论证——省掉的正是过去六次每次都要重付一遍的论证成本。
- **注意力收缩到赛题交付。** 当前实际状态：Phase A 批跑停在 43/125（`ba32eb8`，应用户指示停批），
  距截止 21 天，125 全量 + 技术报告 + 交付面都在关键路径上。ADR-0004 已经关闭过一次基底话题，
  本文补的是关闭的**理由**，而不只是关闭本身。
- **参考采纳有了可复核的形状。** 每条借鉴都要能答「解决了什么」；答不上来的不叫借鉴。

### 负（如实记录）

- **dsh 全套重建的选项被推迟到赛后**（若届时仍有意愿）。spike 已证明地基站得住，
  所以这个选项是真的、代价也是真的：放弃的是一套生产级 multi-agent OS 的现成能力面
  （会话续跑、子进程与终端、插件体系），买到的是 21 天不被基底工作占用。
- **spike 的移植地图归档备用。** 第二波移植地图与量级评估留在 spike 的会话报告里，
  **没有进仓库**；树内可复核的只有 `dsh-app/`（patch 层 + smoke 脚本）与 `f95be86` 的提交信息。
  赛后若重开，这张图要从会话记录里捞，或者重做一遍。
- **宪章不能阻止第五次基底变更，只能抬高它的举证门槛。** ADR-0003 写过一次同类的话，
  这里不重复承诺。

## 何时重新审视

**赛后，2026-09-05 之后。**

在此之前，本宪章不因新工具、新框架、新参考仓的出现而重开——那正是四次基底变更的成因。

赛后重开时第一件事是复核四锚里哪一条随交付结束而失效：目标锚必然失效（赛题已交付），
其余三条各自独立判断。
