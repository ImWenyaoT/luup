# ADR-0003 · TypeScript 全栈复活

## 状态

已接受（有条件），2026-08-14。条件写在「何时重新审视」。

**已收口，2026-08-15**：退出条件的「绿了」分支成立，Python 栈按 ADR-0004 删除。
下文保持原样，是当时的决策记录，不是当前的仓库形状。

## 背景

这是 luup 的**第四次基底变更**：

| # | 日期 | 变更 | 落点 |
|---|---|---|---|
| 1 | 2026-08-08 | eve + AI SDK 起步 | 初始提交 |
| 2 | 2026-08-10 | 编排层迁 `@openai/agents`（TS） | `e161da4` (#2) |
| 3 | 2026-08-10 | 整体切 Python FastAPI，TS 栈全删 | `d9f1485` (#3) |
| 4 | 2026-08-14 | TS 全栈复活，Python 栈转回退路径 | `d584107` 起的 `feat/ts-stack` |

前三次都在两天之内发生，第四次隔了四天。四次这个数字本身就是一条负面证据，
所以这份 ADR 的重点不是论证「TS 更好」，而是把这一次的**具体收益、代价和退出条件**
写死，让它不能再被无成本地翻转。

### 动机

三条，按份量排序：

1. **dsh 借鉴只在 TS 侧可行。** deepseek-harness 是 TypeScript 写的 multi-agent OS，
   它值得抄的东西（合成工具结构化输出、崩溃恢复、错误码归一、接缝组织）都以
   TS 类型系统与 `@openai/agents` 的运行时形状为前提。在 Python 侧重新发明一遍，
   抄来的就只剩「思路」，file:line 级的复核关系断掉 —— 而复核关系正是这些借鉴的价值所在
   （见 `docs/design/dsh-borrowings.md`）。
2. **方向是 multi-agent OS，不是一个 125 题的脚本。** 竞赛是当前的交付物，
   不是终点。往 multi-agent OS 走，dsh 是最近的参照系；参照系与实现同语言，
   后续每一次对照都便宜一个数量级。
3. **luup-old 的五角色资产可直接复用。** 第三次切换删掉的那套 TS 代码（21 文件 2960 行、
   60 用例）不是废稿：五个角色的合同、证据台账、B1–B4 判定的形状都还成立，
   复活的成本是搬运加接线，不是重写。

## 决定

### 采纳

- **五角色流水线**：researcher / hypothesis-generation / evidence-review /
  research-plan / reviewer。固定五阶段串行，两条上界（补证 ≤2 轮、修订 ≤2 轮）
  写在 `src/harness.ts` 的控制流里，不交给任务依赖图算。
- **B1–B4 确定性引用验收**：`src/verify/`。Reviewer 说好之后、终态之前的一道不问模型的门。
- **`node:sqlite` 作为运行事实存储**：零依赖、单文件、单写者锁；重开数据库即把运行中的 run
  判 `interrupted`。取代 Python 期的 `runs/<id>/` 目录制。
- **战役记忆维持文件制**：`memory/` 下的 Markdown，append-only，历史行逐字保留。
  这一条**没有**跟着存储一起换 —— 记忆是给人读的，也是竞赛材料的一部分。
- **Python 栈原地不动，作为 8/20 检查点前的回退路径**。不是「暂时留着」，是显式的 plan B：
  它的 323 个测试在每一波移植后都复跑确认未破。

### 已完成的移植波次

| 波 | 内容 |
|---|---|
| 1 | B1–B4 验收；批跑器 + 熔断 + 单题超时；`sourceIdentity`；失败路径记账 |
| 2 | 战役记忆层 + 消融臂；离线评估指标；预注册协议修订 `amendments[0]` |
| 3 | 合成工具结构化输出；`context_overflow` 错误码；接缝化组织；本 ADR 与借鉴台账 |

30 题子集与协议里的 sha256 承诺一字未动 —— 换栈不是重开预注册的理由。

## 后果

### 正

- dsh 的借鉴关系是 file:line 级可复核的，不是「思路上参考了」。
- 存储从目录制变成单文件 sqlite，批跑的断点续跑、失败记账、事件序号单调性都由
  一个事务边界保证，不再依赖文件系统的原子性假设。
- 接缝集中在 `src/seams/`：模型接线、验收器、Run 记账面、记忆通道各自可换，
  且宽度由类型系统兜底。

### 负（如实记录，不粉饰）

- **这是第四次基底变更。** 四次里有三次发生在两天内，说明前几次的决策依据不足。
  这条记录的存在本身就是代价：任何一个读到这份 ADR 的人都会先问「你怎么保证没有第五次」。
  答案只能是下面的退出条件，不能是保证。
- **Python 期的全部增量（PR #4–#30，2026-08-10 至 08-13）都要重新落到 TS 侧。**
  Wave 1+2 已经覆盖了侦察报告列的 11 项差距；剩下的是交付面与报告材料 ——
  它们不在关键路径上，但也不会自己搬过来。
- **`runs/` 从事实数据降为只读归档。** Python 期跑出来的 run 证据仍然有效、仍然入库，
  但 TS 栈不写它、不读它。跨栈的历史比对因此要人工做一次映射，
  这也是 125 题必须在同一个栈上跑完的原因。
- **两套栈在仓库里并存到 8/20。** 目录不冲突、测试互不影响，但认知负担是真的：
  改一处领域约束要判断它落在哪一侧，`AGENTS.md` 的描述在切换完成前也只能同时指两处。

## 何时重新审视

**8/20 检查点**：TS 栈必须在这一天之前具备端到端跑完 Science-125 Phase A 的能力
（五角色 + B1–B4 + 批跑 + 评估 + 交付面，全绿）。

- **未绿即回退**：不再补 TS 栈，直接用 Python 栈跑 Phase A。竞赛截止 2026-09-05，
  Phase A 的机时不能拿来赌基底。这条不需要再讨论，触发即执行。
- **绿了则收口**：Python 栈在 Phase A 跑完后删除，`AGENTS.md` 与 `docs/design/architecture.md`
  同步改指 TS 侧，本 ADR 状态改为「已完成」。

除此之外不因为「新工具/新框架看起来更好」重开本决定 —— 那正是前三次切换的成因。
